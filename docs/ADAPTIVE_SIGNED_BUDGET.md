# Phase 3: active ML-guided authenticated KIE under a strict budget

## Scientific question

Can *actual* signed KIE transmissions be reduced while preserving detection
latency and minimizing false alarms, and does normal-only ML priority improve
over a round-robin scheduler under an identical one-of-two signer budget?

**This is an honest budget study, not a claim that adaptive ML wins.** The
experiment records real independently signed HTTP/1.1 test-agent responses
and separately measures all eight Open5GS NF SBI HTTP/2 endpoints. The two
test agents are co-located in the NRF and SMF network namespaces. They
are not implemented as standard NF services, nor do they sign Open5GS's
internal signaling counters.

## Three strategies (all executed live)

| Strategy | Authenticated challenge requests per tick |
| --- | --- |
| `full` | 2 (NRF, SMF) |
| `rotation` | 1 alternating signer, except 2 for initial state |
| `ml_adaptive` | 1 signer selected by normal-only IsolationForest novelty, last signed counter discrepancy and observation age; 2 on initial tick |

The unsupervised IsolationForest is trained **only on earlier, real, honest
signed KIE replies** from `signed_kie.csv`. It does not see the labels for
this follow-on adaptive experiment. The bounded-age safeguard prevents a
persistent blind spot from unchecked network functions. All policies
use precisely the same maximum of one signed query per tick (after tick zero)
for rotation versus ML-adaptive.

The two test signers represent an intentionally small architecture. Savings
are computed **only for signed challenge requests**. All eight NF HTTP/2
transport probes continue every tick and are explicitly **excluded** from
the savings denominator. Application payload bytes omit headers/framing.

## Controlled interventions and negative controls

Each campaign records all 8 NF HTTP/2 responses, with independent signed
KIE queries to the selected test agent(s). Target order is randomized for
each trial, and policy campaign order is shuffled by the recorded seed.

- Baseline: stock Open5GS core + normal signer reports.
- `benign_delay`: 120-ms signed-report delay with honest counters;
  **negative control** to test alarm specificity.
- `spoof`: reports with valid MAC, fresh challenge binding, and *stale
  cumulative counter*, with **NO artificial delay**. Both NRF and SMF
  agents are targeted in randomized order, while the native NFs remain up.
- `recovery`: honest signed reports resume.

The independent observer counts successful challenge-replies, binds the
first counter to a per-trial baseline offset and tests discrepancy on each
new signed response. Counters are signed by the experimental agent but
their semantic truthfulness is NOT established by the signature alone.

For a node that is skipped, signed fields indicating a NEW probe are
missing (not fabricated). The last verified discrepancy and its age are
retained. An alarm may persist until a newer honest signed response clears
it, including during a recovery interval. This is included as a legitimate
false alarm in row-level FPR.

## Outcomes saved in GitHub Actions artifacts

- `results/adaptive_signed.csv`: eight NF/clock ticks and which of the
  two signers were ACTUALLY queried; signed query bytes, observed discrepancy,
  per-agent age, label and running alarm.
- `results/adaptive_signed.metadata.json`: exact seed, randomized
  intervention sequence, earlier normal-only training source, transmission
  counts and NF test-agent caveats.
- `results/adaptive_signed_metrics.json`: full versus rotation versus ML
  signed-query totals and fractions, true/false positive row counts,
  episode-level first-alert delay (ticks), missed attack episodes,
  confidence intervals using Wilson scores, benign-delay false alarms.
- `results/adaptive_signed_metrics.csv`: comparison table for analysis.

Strict validity checks require *all eight* NF rows per tick, no duplicates,
signed responses for every sent KIE, correct one-query budget for selective
policies, and a genuine live data provenance field. There is no synthetic
fallback to get a successful CI run.

## Major limitations

The ML only schedules signed probe recipients. The binary anomaly decision
is currently a **deterministic verified counter-inconsistency test**; it is
*not* generated by the earlier graph-temporal GNN. The GNN is studied
separately in Phase 2. Results thus isolate the impact of ML scheduling
versus a simple regular schedule, not the claim of an end-to-end adaptive
GNN. Combining the trained GNN with active KIE selection is a separate
scientific task.

Trials share one Docker 5G SA core on a single hosted runner and are not
independent operator deployments. Different policies have **independently
timed interventions**, so their results are not paired samples. Neither
confidence intervals on individual tick rows nor four short attack episodes
prove generalizability or statistical superiority. A true deployable study
needs native NF counter access, operator-representative load variation,
different topologies, independent repetitions and calibrated challenge
scheduling costs.

## Running

The default `smoke` GitHub Actions workflow tests two trials per policy,
both signer targets, and a benign-delay negative control.
The manually selected `research` mode increases repeated trials and phase
durations. Both run after Open5GS/UERANSIM attestation and the Phase 1/2
collection steps.

Run [the experiment workflow](../.github/workflows/experiment.yml) and
download the **run-specific** `5g-live-evidence-*` artifact. Interpret all
reported values in conjunction with the intervention manifests.

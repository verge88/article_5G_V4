# Phase 2: authenticated laboratory KIE + trainable temporal GNN

This extends the verified Open5GS/UERANSIM integration from Phase 1. It is
executed **inside the same running 5G SA lab**, after successful real UE
registration, PDU data traffic and the original HTTP/2 SBA measurements.

## Design boundary: a signer is not a native network function

Two independently instrumented **NF-co-located agents** run in Linux network
namespaces of NRF and SMF on the test-only port 18080 (HTTP/1.1). This second
port shares the core network path but is **not** standard Nnrf/Nsmf, native
Open5GS code, production SBA HTTP/2 nor a new 3GPP procedure. Real NF HTTP/2
availability is measured separately in every tick. No claims are made about
cryptographic authentication of the unmodified NF itself.

The hierarchy has an external observer (logical master) and instrumented
agents (slaves). Every signed KIE challenge contains NF identifier, strictly
increasing sequence number, 128-bit random nonce, wall-clock timestamp and
HMAC-SHA256 over deterministic JSON. A different subkey is derived per NF.
The agent authenticates the request, checks timestamp freshness (60s),
rejects old sequence/repeated nonce, and returns a signed response bound
to the same sequence and nonce. The independent observer verifies the reply
MAC, challenge binding, and response freshness before accepting the report.

An ephemeral 256-bit **test-only** master key is generated by the CI runner.
It is not uploaded as an artifact or printed. On production networks, use
proper key distribution, rotation, mutual TLS and secret storage.

## Precisely what the spoof scenario models

Only the NF-co-located **experimental reporting agent** is instructed to
dishonestly maintain an old cumulative challenge receipt count. It still
produces a valid HMAC and an internally consistent total/components sum.
The independent master observes one new verified KIE challenge response
per tick and notices that the signed report count no longer increases.
An additional 120-ms server-side response delay is injected while the
agent continues to sign the stale report. The real Open5GS SMF remains up,
and its separately measured HTTP/2 endpoint remains on the main core
network. This is a lab test of **signed but untruthful report data**.

The KIE agent counter measures **its own challenge receipts**, NOT SMS,
PFCP, 5G SBA signaling message volume or NF internal performance counters.
Consequently this does NOT demonstrate detection of malware, subscriber
hijacking, true stealthy NF compromise, or full dissertation-grade
independent auditing of native NF reports. It validates only the
signed-challenge mechanism and a carefully scoped provenance invariant.

## Campaign

In each of four collection trials, on the same live Open5GS core:

1. Baseline: stock 5G NF services and honest signed agents.
2. `spoof_smf`: agent still signs but its reported challenge counter freezes;
   its response is delayed by 120 ms. Ground truth labels SMF rows anomalous.
3. Recovery: agent resumes reporting a current counter and normal timing.

Independent observer records all eight NF HTTP/2 availability/RTT values
per tick, plus signed-KIE HMAC outcomes, round-trip time, provenance
counter discrepancy and report-sum invariant for the two instrumented NF.
No synthetic benchmark rows are mixed into published live CSV files.

## Trainable model and leakage controls

`experiment/temporal_gnn.py` implements a **real trained neural** model using
PyTorch on CPU, not a renamed ExtraTrees estimator:

- Fixed documented NF-relationship graph (hypothesized from service roles,
  not extracted from deep packet inspection) with normalized neighbor mixing.
- Learned graph projection for each NF/time, followed by a GRU over the last
  four causal ticks and node-level anomaly logits.
- Learned weights from training trials only and early stopping on a disjoint
  validation trial, classification threshold selected on validation only.
- Completely held-out last trial used once for reported generalization.
- Same random seed and data partition across the three GNN ablations.

We compare: graph+temporal+signed KIE, temporal+signed KIE without graph
edges, graph+temporal without KIE; plus local Random Forest,
hierarchical Random Forest without KIE and hierarchical Random Forest with
signed KIE. This quantifies the *relative* role of active signed control and
graph context. High F1 is not evidence of previously unknown attacks.
A fixed graph/topology and a single Docker host are substantial threats
to external validity. Trial partition isolates collection cycles but not
independent physical networks or attack mechanisms.

Files:

- `results/signed_kie.csv`: raw independently collected node/tick data
- `results/signed_kie.metadata.json`: source, trial metadata, intervention
- `results/signed_gnn_metrics.json`: train/validation/test partition, six
  models, F1, AUC, PR-AUC, FPR, confusion counts and episode delay
- `results/signed_gnn_metrics.csv`: result comparison for manuscript tables
- `results/open5gs-docker.log`: separate service logs of the real lab

**Do not present the fixed-service graph as discovered topology, real NF
compromise as simulated agent tampering, or this controlled dataset as an
operator-grade 5G attack trace.**

## Next validation goals

A production-like extension would instrument stock Open5GS NF APIs or
provision a custom service-based function with fully authenticated HTTP/2
report transfer, privileged but isolated access to real NF message counters,
compromised native NF telemetry, independent packet-based ground truth,
several topology/workload choices, randomized intervention timing,
repeated multi-seed evaluations, statistical intervals, and realistic
adversarial strategies against adaptive probing.
